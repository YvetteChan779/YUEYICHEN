Overview

Deploying speech-controlled grasping on Jetson AGX Orin exposed a hard interface problem: far-field speech, TTS echo, ASR endpointing, small-object grounding, and post-grasp verification all fail through different interfaces. PLAN-B is a speech-to-grasp interaction stack: 16 kHz ALSA PCM enters a cloud-first ASR route, qwen3.5-flash converts clean commands into JSON intents, a Qwen-compatible VLM supplies source-pixel bbox priors for SAM3 box/text masks, and a 13-mixin ROS2 FSM publishes stamped PerceptionResult geometry into the grasp execution chain.

  • Engineered a 3-tier cascaded VAD quality gate (adaptive energy + software AGC + stateful Silero v4 ONNX h/c [2,1,64]), field-calibrated on-site with noise around −46 dB and speech around −39 dB, lifting far-field hit rate from 0% to 92%.
  • Architected a cloud-first 4-engine streaming ASR router (cloud_qwen3 / cloud_paraformer / local Qwen3-ASR TRT / FunASR) with envelope AGC v5, cloud endpointing ownership transfer, TTS playback zero-fill echo guard, and rapid-stitch recovery for split verb-head fragments.
  • Designed dual-path NLU (six action regex templates + wake/chat handling + qwen3.5-flash JSON NLU, temperature=0, max_new_tokens=28) with a 5-layer semantic defense cascade, plus VLM bbox + SAM3 box/text grounding on one original-pixel coordinate plane, lifting reported SAM3 mask success from 4/44 to at least 90%.
  • Integrated a 13-mixin pipeline FSM with standalone grasp_check_server verification (SAM3 target+hand batch2, median<55 mm, P25<45 mm, frac<3 cm ≥ 2%, frac<5 cm ≥ 8%, no z_fallback) and a separate optional vlm_or_tactile serial confirmation path.

System Architecture

My scope: I owned the voice front-end, cloud_qwen3 / paraformer ASR routing, qwen3.5-flash NLU, VLM-SAM3 grounding contracts, 3D grasp verification integration, TTS feedback guards, and the 13-mixin closed-loop state machine. Downstream navigation, IK planning, and motor control were collaborator-owned.

Voice Frontend: Field-Calibrated 3-Tier VAD

The VadQualityGate class implements a 3-tier cascaded quality gate. Layer 1 (pre-AGC): adaptive energy filtering with self-calibrating noise floor — a sliding window collects non-speech energy history, computes P10 percentile as noise floor, and sets threshold = floor + margin. On-site measurements: noise ≈ −46 dB, speech ≈ −39 dB, margin = 6 dB (tight enough to reject background chatter). Layer 2: software AGC normalizes RMS to −20 dBFS target (max gain +30 dB, upward-only — never attenuates). Layer 3: Silero v4 ONNX on CPU, processing 512-sample chunks (32 ms @ 16 kHz), with h/c separated hidden state [2,1,64].

The critical fix was enabling stateful Silero inference across 64 ms audio blocks. Without stateful_silero=True, each ROS audio callback (1024 samples = 2 Silero chunks) ran Silero from cold-start h/c = zeros — far too little context for the RNN to distinguish weak speech from noise. Field logs showed speech=0 across all windows despite peak amplitude 26063. With cross-call state preservation, the RNN accumulates context naturally, and speech detection recovers.

Layer 4: ASR Output Post-Filter

A 4th layer filters ASR output before downstream dispatch: hallucination detection (frozen set of 20+ phantom phrases like “字幕by”/“感谢观看”), rambling detection (≥2 of: filler prefix, particle density ≥20%, hesitation words ≥2, bigram repeat ≥3), repeated phrase removal (regex (.{2,})\1+), and non-CJK/English ratio (>30% foreign script → reject). This prevents ASR noise from polluting the NLU.

Far-field Silero hit rate: 0% → 92% • VAD discrimination: noise < 0.01, speech > 0.99 • Noise floor converges in ∼15 s

Streaming ASR: Cloud-First 4-Engine Router

The StreamingAsrNode hosts a pluggable engine router (build_engine()) selecting one of 4 ASR backends at launch. Engine choice determines the audio path, endpointing ownership, and AGC strategy — the node auto-detects engine capabilities via hasattr(engine, 'set_on_sentence_callback') and adapts accordingly.

Envelope AGC v5: Silence-Creep + Fast Peak Ceiling

The cloud_qwen3 path applies a 5-iteration envelope-following AGC (_apply_envelope_agc) before feeding raw audio to the cloud. Key design: (1) fast peak ceiling — if peak × gain > 0.85, gain is instantly clamped to 0.85/peak (no slow release, preventing hard clipping that freezes cloud ASR); (2) envelope follow — when rms > noise_floor (−38 dBFS), gain tracks toward target/rms with attack=0.30 / release=0.30; (3) silence creep (v5) — when rms ≤ noise_floor, gain slowly rises toward max_gain at attack × 0.2 = 0.06 per chunk (~2.4 s to max), pre-staging for the next far-field utterance; (4) soft-clip — tanh compression above knee=0.9, eliminating harmonic distortion from any residual clipping.

Cloud Endpointing Ownership Transfer

For cloud engines, the node transfers sentence boundary detection to the cloud: engine_owns_endpointing = True. The cloud's sentence_end callback (_on_cloud_sentence) directly drives publish_final. Local EOU is disabled except as a max_utterance_sec=20s timeout watchdog. This eliminates the destructive pattern where local EOU triggered session.stop()+start() on every silence gap, causing partial count freezes and race conditions between feed() and stop().

Rapid-Stitch: Short Verb-Head Buffering

Cloud ASR sometimes splits a single command at word-boundary pauses (e.g., “把” + 0.8 s pause + “棕色玩具熊放进白色篮子里” → two finals). The _handle_qwen_final method detects short verb-head finals (≤3 chars, prefix in {把,拿,放,抓,给,帮,请,...}) and buffers them for 1.5 s. If a continuation final arrives within the window, the two are stitched; otherwise the short head is published alone.

ASR streaming partial: 150–300 ms • Session survival: heartbeat → no 23 s SDK timeout • AGC v5 far-field recovery: ~2.4 s silence-to-max-gain

Dual-Path NLU & VLM-SAM3 Grounding

Dual-Path Intent Parsing

The VoiceCommandParser operates in regex_then_llm mode. Fast path: six action regex templates plus wake/chat phrase handling extract intent (pick_up / pick_and_place / place_only / move_to / chat / unknown) and entities from clean commands in <1 ms. LLM path: qwen3.5-flash (TRT-LLM or OpenAI-compatible HTTP) with a structured system prompt defining 6 intent types, noise classification rules (garbled ASR, background speech, filler phrases), and entity fields (target_object, quantity, location, object_en, location_en). Generation: temperature=0, max_new_tokens=28. A chat_fallback regex catches clear questions that the LLM occasionally misclassifies as unknown.

VLM Bbox + SAM3 Box/Text Grounding

The perception pipeline feeds NLU output to a Qwen-compatible VLM HTTP route for bounding-box extraction, then to SAM3 with box + English text prompts. The critical contract is that VLM bbox decoding and SAM3 masks share the same original image pixel plane: the bridge maps 0-1000 bbox outputs to source-pixel xyxy and passes input_boxes_pixel_xyxy into SAM3, while SAM3 handles its own letterbox preprocessing internally. A color-to-VLM routing fix moved color/brand discrimination from SAM3 HSV heuristics to the VLM bbox stage, with HSV rerank kept only as rollback.

5-Layer Semantic Defense Cascade

Dirty data at any stage cascades into wrong targets and failed grasps. Five ordered defense layers intercept errors progressively: (1) Whitelist recovery — regex dictionary maps ASR noise to known objects (e.g., phonetic corruptions); (2) Color backfill — if ASR omits a color prefix present in the original command, the parser re-injects it from _ZH_COLOR_PREFIXES; (3) Hallucination stripping — removes phantom locations invented by the LLM; (4) Sentinel filtering — translate_for_sam3 checks against a known-object dictionary to prevent dictionary pollution (e.g., an unknown object mapping to a wrong English word); (5) VLM-SAM3 contradiction — if VLM gives a concrete bbox but SAM3 returns an empty/too-small mask or a low-confidence VLM-backed result, the result is rejected before it can pollute tracking cache.

SAM3 mask success (small targets): 4/44 → ≥90% • Color/brand routing moved to VLM • NLU intent: 6 types + noise classification

Closed-Loop FSM & 3D Grasp Verification

13-Mixin Pipeline Architecture

The MultimodalPipelineNode uses mixin-based separation of concerns: WakeWordMixin, NavMixin, GraspFeedbackMixin, TtsMixin, LongWaitFeedbackMixin, PlaceVerifyMixin, AsrMixin, Sam3Mixin, ArmMixin, CameraMixin, RdkMixin, BypassMixin, and OrchestrationMixin. Pipeline stages: IDLE → NAV_TRACK_HEAD → NAV_REACHED_FLUSH → GRASP_RESEG_HEAD → GRASP_TRACK_LEFT → PLACE_TRACK_HEAD. A DialogManager handles conversation follow-up windows (12 s) and clarification timeouts (12 s).

grasp_check v1.0.0: 3D Multi-Feature Voting

After each grasp attempt, the GraspFeedbackMixin transitions through idle → executing → verifying → retrying/aborting. The standalone grasp_check_server runs SAM3 once with target and robotic-hand prompts, reconstructs both masks into 3D, and gates hand-object nearest-neighbor overlap with median distance < 55 mm, P25 < 45 mm, frac within 3 cm ≥ 2%, and frac within 5 cm ≥ 8%; pure depth z_fallback is disabled. In the pipeline-level vlm_or_tactile route, VLM failure fails directly, while VLM success opens a serial tactile polling window for confirmation.

P0 Cascading Failure: 7-Step Root-Cause Audit

A missing ok=True in _bg_write_shm() caused stale frame reads → degraded masks (<93 px) → infinite retry. Audit traced: flag → stale cache → VLM old frame → SAM3 misalignment → mask collapse → depth failure → retry loop. The report changed this P0 flow from four failed retries to closed-loop success.

Technical Highlights

Envelope AGC v5

5-iteration design: fast peak ceiling (instant clamp at 0.85), envelope follow (attack/release=0.30), silence creep (slow rise to max gain in ~2.4 s), and tanh soft-clip. Solves the "near-to-far transition" where gain freezes at +0 dB after loud speech.

Cloud Endpointing + TTS Echo Guard

All PCM frames, including silence, stay in the cloud stream so server-side endpointing can fire; default config disables barge-in, while TTS playback still zero-fills echo frames and the optional interrupt path remains guarded.

Source-Pixel VLM/SAM3 Contract

The VLM bbox bridge decodes 0-1000 outputs into original-pixel xyxy and passes input_boxes_pixel_xyxy to SAM3, avoiding coordinate drift between VLM grounding and SAM3 masks.

3D Grasp Voting Boundary

Standalone grasp_check is SAM3 target+hand batch2 plus 3D overlap with no z_fallback; tactile belongs to the separate pipeline-level vlm_or_tactile confirmation route.
